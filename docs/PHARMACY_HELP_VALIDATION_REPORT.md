# PLS Pharmacy help validation

## Evidence boundary

The corrective requirement is a practical, page-by-page software manual, not an accounting course. [Inventory](PHARMACY_PAGE_INVENTORY.md) and [coverage baseline](PHARMACY_USER_GUIDE_COVERAGE.md) were written before rewriting the reader/content.

Prior to the correction: 126 frontend tests and TypeScript passed; 61 focused backend tests passed. These results validate their tested behavior, not the completeness of a software manual. The expanded browser run was interrupted and is not recorded as passed.

## Publication gates

- Every operational route, including dynamic detail pages, maps to its own relevant practical help.
- Page guides follow: opening path, purpose, interface, operations, outcome, verification, recovery, next steps.
- Each documented operation has numbered steps and specific verification.
- Controls/fields are grounded in the inventoried source, not invented from accounting terminology.
- Cross-page tutorials link to page procedures, respecting page access and second-person actions.
- Technical definitions are optional and subordinate.
- Synthetic screenshots are clearly marked; no live patient/employee/supplier/financial information is captured.
- Runtime-unverified operations remain explicitly identified.

## Outstanding acceptance

Full action-level runtime execution, authenticated live-deployment validation, representative-user training-free task completion and owner acceptance are not established. Do not equate catalogue shape tests, article count or screenshot existence with those outcomes.

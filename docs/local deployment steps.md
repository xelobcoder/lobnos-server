# Local deployment steps

1. **Prepare the Windows device.** Install MySQL 8, confirm the database service starts after reboot, and provision the facility database and its initial administrator. For an upgrade, take a verified backup of the facility database and any control database. Keep the previous installer and configuration for rollback.
2. **Check the release on the build machine.** Use matching frontend and backend revisions. Run `pnpm install --frozen-lockfile`, then run `pnpm test` and `pnpm build` in both repos. In `lobnos/desktop/config/backend.env` and the backend `.env`, confirm the target facility, MySQL host and port, database, and dedicated database account. Keep build credentials private.
3. **Build the Windows installer.** In `lobnos-server` on the authorized build machine, run `pnpm.cmd run desktop:configure-install-password` if the installer password has not been configured, then run `pnpm.cmd run desktop:build:licensed`. Use the new installer from `lobnos/dist-electron`. The installer is facility-specific and carries database connection settings.
4. **Test the installer on a spare Windows device or VM.** Prepare its test database, run the new installer, enter the installation password, and activate with a signed license for that device. Reboot. Sign in, create a synthetic registration, save and open a test result, and verify backup and restore against a test database. Use the same checked installer on the intended device after these checks pass.
5. **Before uploading to the VPS.** Back up the control and tenant databases and retain the previous release. Stage both matching revisions with the VPS production environment. Build, migrate or bootstrap as required, then restart only the named PLS services. The legacy `deploy.sh` scripts restore old package files and restart every PM2 process. Check public HTTPS login, master login, tenant switching, Copy test setup and a historical Laboratory report. Confirm the reverse proxy forwards the public host and scheme and no browser redirects go to localhost. Initialize the master account on the VPS only if its control database does not already have one.
